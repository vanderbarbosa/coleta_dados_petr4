**Previsão implementada (jun/2026):** Script 04 salva `modelo_xgb_fusion.json` + `modelo_meta.json` (retorno/volatilidade recentes, métricas). Backend `POST /api/prever` (precisa do petr4, imports torch/transformers LAZY): FinBERT calcula sentimento → checa relevância temática (TERMOS_RELEVANCIA_ESTRITA) → XGBoost prevê direção do próximo pregão. Veredito honesto: alta se P(alta)≥0.55, baixa se ≤0.45, senão indefinida; irrelevante → "sem influência". Frontend: página "Avaliar notícia". Testado por HTTP (1ª chamada ~20-30s p/ carregar FinBERT; cacheia). **Backend agora roda no petr4** (não mais base) p/ suportar a previsão.

**Previsão v2 (jun/2026):** relevância passou a usar a taxonomia COMPLETA (152 termos) + detecta categoria (antes só 13 termos estritos → frases como "Estreito de Ormuz" eram ignoradas). Adicionada **leitura econômica setorial** (qualitativa, Kilian/Hamilton): choque de oferta (CAT2/3/4/5) com tom negativo → petróleo sobe → favorece a Petrobras (produtora) → veredito ALTA, mesmo com sentimento negativo. Responde à crítica de Hisson (mercado × ativo). O response traz 2 sinais: `leitura_setorial` (econômica, vira o veredito principal) e `leitura_modelo` (XGBoost estatístico, P(alta), exibido em paralelo com a ressalva de ~53% acc).

**Previsão v3 (jun/2026) — camada semântica de evento:** `_analisar_direcao` distingue RESOLUÇÃO (acordo, fim de greve, cessar-fogo, normalização) × DISRUPÇÃO (greve, ataque, intervenção) via keywords, corrigindo quando o tom do FinBERT não reflete o sentido (ex.: "greve termina" = positivo). Mecanismo por categoria: EMPRESA (CAT1/CAT6) → resolução=alta/disrupção=baixa; MERCADO/oferta (CAT2/3/5, CAT4 se não-Petrobras) → disrupção=alta (preço sobe, favorece produtora)/resolução=baixa. Corrigiu o caso "greve termina após acordo" (BAIXA→ALTA); 6 casos validados. Badge `evento` na UI/jornada. É heurística fundamentada (Kilian/Hamilton), transparente, ao lado do modelo estatístico — responde à crítica de Hisson (mercado × ativo). Backend sem --reload: reiniciar p/ pegar mudanças. Visual refeito: CSS profissional (hero, cartões hover, badges, spinner, card de veredito colorido). **Jornada animada (`Jornada.jsx`):** ao avaliar uma frase, mostra um pipeline HORIZONTAL (esteira) com 6 etapas (frase→sentimento→relevância/categoria→leitura econômica→XGBoost→veredito). Cada etapa é uma **engrenagem (SVG cog)** que gira enquanto processa (sentidos alternados), conector com "spark" correndo, auto-scroll p/ a etapa ativa. **Sons** sintetizados via Web Audio (`src/som.js`, sem arquivos): zumbido ao engrenar, ding ascendente ao concluir, fanfarra final (sobe=alta/desce=baixa); botão Som on/off (áudio só toca após o clique em Avaliar). Finale full-width: gráfico de preço SVG desenhado subindo/descendo + botão Repetir. Para rodar/desenvolver: o servidor Vite tem HMR; backend sem --reload precisa reiniciar p/ pegar mudanças no app.py.

**Previsão v4 (jul/2026) — cessação de valor + acentos:** `_analisar_direcao` (empresa) passou a detectar CESSAÇÃO DE VALOR AO ACIONISTA (corte/suspensão/redução de dividendos/JCP/recompra, ou prejuízo) → BAIXA, com prioridade sobre resolução/disrupção/sentimento — corrige o caso "petrobrás deixará de pagar dividendos" que o FinBERT lia como positivo (ignora a negação). Simétrico à lógica de resolução (fim de coisa ruim→alta). Também: casamento de termos da taxonomia agora é INSENSÍVEL A ACENTO (`_sem_acento`/NFKD no backend; `sa()`+`\p{Diacritic}` no JS) — antes "petrobrás" com acento não casava com "Petrobras" e caía em "sem influência". Aplicado em `app.py` E `previsao_local.js` (mantidos espelhados); controles positivos preservados (dividendos recordes→alta, choque de oferta→alta). Bom argumento p/ banca: mostra por que a leitura econômica supera o sentimento bruto. Backend sem --reload/run_app.bat → após `git pull`, REINICIAR o backend p/ pegar a mudança.
